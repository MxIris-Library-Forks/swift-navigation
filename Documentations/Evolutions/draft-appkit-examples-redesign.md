# Draft - macOS 示例改用侧边栏外壳与系统设置式排版

- **状态**: In Progress
- **创建日期**: 2026-11-14
- **最后更新**: 2026-11-15
- **实现分支**: `appkit-examples-redesign`

## 摘要

AppKit 案例里有一半页面是照着 UIKit 案例逐行移植的：几个按钮堆在窗口正中，状态用 ✅/❌ 写进按钮标题；较新的页面从左上角往下排，每节一个粗体标题，能用但简陋。Basics 页里由布尔值弹出的 sheet 只有一行「Hello!」，没有任何按钮，弹出来就关不掉；Wi-Fi 案例的网络详情 sheet 也一样，在「忘记网络」的确认框里取消之后就没有出口。

第一轮把全部 AppKit 案例（15 个案例页，加上 Wi-Fi 案例的 3 个页面）改成「系统设置」那样的分组排版，并让每个弹出的 sheet 都能关掉。看过之后，整个示例的外壳仍是从 iOS 沿用的逐层进入的列表（Case studies → AppKit → 页面，换页要先返回），不像现代的 Mac App；旧版写在按钮标题里的弹出状态，也只剩部分行有一段灰色文字。第二轮把 macOS 上的外壳换成侧边栏加详情，并在每个会弹出或跳转的行上标出当前的导航状态。

## 方案

- **外壳**（只改 macOS，iOS 保持上游原样）：
  - 新文件 `SidebarRootView.swift`：`NavigationSplitView` 的侧边栏按「框架 · 主题」分组列出全部 SwiftUI 与 AppKit 案例，每个带一个 SF Symbol 图标；详情区显示选中的案例，标题下用副标题注明是 SwiftUI 还是 AppKit。
  - 案例说明从「About 按钮 + 带 Close 的 sheet」改成工具栏 ⓘ 按钮弹出的 popover。
  - 详情区包一层 `NavigationStack`，SwiftUI 案例里的下钻照常推入。
  - SwiftUI 案例在 macOS 上的表单用分组样式，与 AppKit 案例一致。
- **共享排版**放在已有的 `AppKit+CaseStudySupport.swift`：
  - 页面：一列分组，放在可以滚动的区域里，靠上、水平居中，有最大宽度。滚动区域铺满整个详情区，列宽只以弱于 SwiftUI 宿主尺寸的优先级偏向 640 点，不会反过来把整页拉窄。
  - 栈导航的每一页（`WindowBackgroundView`）铺一层与窗口相同的背景材质：推入的新页从右侧滑进来压在旧页上，没有背景就会透出旧页。
  - 分组：上方一行粗体标题，中间一个圆角框装着若干行，行与行之间画分隔线，下方可以有一段说明。
  - 行：左边是名称，右边是状态和控件；表格、画布、日志这类内容占满整行。
  - 导航状态标记 `PresentationStateView`：绿色对勾加「Presented」，有值时带上值（「Presented: 42」）；没弹出时是灰色叉号加「Not presented」。
- **每页只换排版和状态显示**，演示的 API 和行为不变。所有会弹出内容的行都带状态标记；栈导航的状态是路径，显示在「Path」一行。
- **sheet 都能关掉**：弹出的内容都有 Done 按钮，回车可以触发；按 Esc 也能关，做法见决策日志。

落地步骤（每步各自编译通过）：

1. 共享排版；Basics 与 Wi-Fi 网络详情的 sheet 加上关闭的办法。（已完成）
2. 其余页面逐页换成分组排版。（已完成）
3. 编译 CaseStudies 的 macOS 版，启动 App 逐页截图检查，修排版问题。（已完成）
4. macOS 外壳换成侧边栏加详情，说明改到工具栏 ⓘ，SwiftUI 案例用分组样式。（已完成）
5. 全部 AppKit 案例的弹出行加上状态标记，类型擦除路径页加上「Path」一行，Wi-Fi 页加上「Destination」一行。（已完成）
6. 重新编译，启动 App 截图检查外壳和各页的状态标记。（已完成）
7. 栈导航的页面铺上窗口背景，表单的列宽改成不会拉窄页面的弱偏好；连续截帧检查推入转场。（已完成）

没有询问就采用的假设：

- 分组标题照「系统设置」用粗体，不用选样式时预览里的全大写。
- 共享排版只用 AppKit，不用 AppKitPlus：多数案例只依赖 AppKitNavigation，读者在页面代码里看到的应当只有这个库的用法。
- 各案例的说明文字保持原样，只是改由 ⓘ 弹出。
- 侧边栏的分组沿用原来两个列表的分组和顺序，SwiftUI 在前、AppKit 在后，分组名前加框架名区分；启动时不预先选中任何案例，详情区提示先在侧边栏里选，每个窗口记住自己上次选的案例。
- 每个窗口为每个 AppKit 案例只创建一次视图控制器，切到别的案例再切回来，页面保留原来的状态；SwiftUI 案例切回来是新的一页。
- macOS 侧边栏里的 SwiftUI 案例清单与 `SwiftUICaseStudiesView` 的清单各写一份：iOS 上仍用后者。以后合并上游新增的 SwiftUI 案例，两处都要加。
- `RootView` 去掉 AppKit 入口，`CaseStudy.swift` 里只给旧 AppKit 列表用的按钮和 result builder 分支一并删掉；iOS 的外壳与 UIKit 案例不动。
- 状态标记的文字与界面其余部分一样用英文。
- Presentation styles 页的文档窗口里那几个 sheet 和工具栏 popover，按钮在文档窗口里，主页面单列一组只显示它们的状态。
- 类型擦除路径 `UINavigationPath` 只公开元素个数，所以那一页的「Path」只显示有几个值。
- Wi-Fi 设置页的行是网络列表，不适合逐行加标记，改在列表顶部加一行「Destination」，显示正在连接或查看详情的是哪个网络。
- NSControl bindings 页原先把模型里的颜色涂满整页背景，改为只由颜色井显示：整页背景会盖掉分组框的层次。默认颜色从窗口背景色改成系统蓝，否则颜色井看起来是空的。
- Focus 页原先把有焦点的文本框涂成浅灰，深色模式下很刺眼，改成把那一行的名称染成强调色。
- Basics 页的 sheet 内容从 SwiftUI 改用案例共用的 AppKit 视图控制器，与其他页面的 sheet 一致；它的 Done 按钮清空状态，演示由状态关闭。Basics 模型里装打开面板提示语的属性从 `alert` 改名为 `openPanelMessage`，那里弹的早就不是 alert。
- Animations 页的圆默认改用系统蓝，颜色循环最后也回到系统蓝：原来的黑色在深色模式下几乎看不见。
- Wi-Fi 设置页本来就是分组列表，只把分组框、宽度和边距对齐到其他页面；连接网络的面板给 Join 配上回车、给 Cancel 配上 Esc。

## 后续项

- 栈导航返回时，滑出去的那一页只画出背景、内容不显示。原因已查明：AppKitPlus 的视差与滑动转场（照它移植的 UXKit）在动画一开始就把离场页的 frame 设到容器外，而 AppKit 只重画视图在窗口里的部分，途中被标脏的内容全成了空白。页面透明时被掩盖了，看起来只是根页滑回来。已在 AppKitPlus 的 `fix/transition-leaving-page-content` 修好（AppKitPlus 提案 transition-leaving-page-content），合进了它本地的 `main`，还没发版。AppKitPlus-Release 发出新版后，把本仓库的依赖升上去即可，示例这边不用改。
